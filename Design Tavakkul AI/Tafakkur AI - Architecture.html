Tafakkur AI System Architecture v0.1 · solo / small team
Production-ready system design

Think, learn, act
and reflect — daily.

Tafakkur AI is a local-first, on-device AI companion for personal growth on Apple platforms. It unifies productivity, learning, spiritual reflection, career and finance behind one private coach — Murabbiy — that plans your day, teaches you, and reflects with you, without your data leaving the phone.

SwiftUI · iOS 18+ MVVM-C + Clean Apple Intelligence / Core ML SwiftData + CloudKit Offline-first
01

Vision & value proposition

Why this exists, and the one thing it does better than anything else.

Most growth apps are single-purpose silos — a habit tracker here, a language app there, a journal somewhere else. None of them know you across domains. Tafakkur AI's wedge is a single on-device model of the user that every module reads from and writes to, so the coach can reason across your day: it knows your interview is Thursday and your focus peaks before noon and that tafakkur matters to you — and plans accordingly.

PromiseOne private coach

A daily AI brief that plans, teaches and reflects — grounded in a memory of your goals, habits and progress.

MoatCross-domain memory

Shared, on-device personalization store. The more you use it, the better every module gets — and competitors can't copy your data.

PrinciplePrivate by default

Inference runs on-device. Nothing leaves the phone unless you explicitly enable iCloud sync. Trust is the product.

Tafakkur AI is a daily ritual, not a destination. The loop is designed so the coach earns a few minutes of trust each morning and each night.

07:30

Open to a calm reflection prompt + gratitude. Sets intention before the feed.

AI daily brief

Murabbiy reads calendar, sleep, goals and progress, then proposes a realistic plan — focus blocks, one lesson, the highest-leverage task.

06

AI system design

How on-device intelligence actually works here.

The AI layer is deterministic plumbing around a non-deterministic core. Each coach turn is a pipeline: gather context → recall memory → compose a constrained prompt → run on-device → filter → act → write memory back.

Request pipeline

1
ContextBuilder

Assembles a structured snapshot: time, calendar, today's plan, active goals, recent reflections, streaks. Strictly typed — no free-form dumping.

MemoryStore (recall)

Pulls the user model — long-term goals, learned patterns ("focus peaks 8–11am"), preferences, and recent embeddings via NaturalLanguage for semantic recall.

PromptComposer

Renders a versioned template: system role (Murabbiy persona) + capabilities + context + memory + the user turn. Output is schema-constrained (guided generation) so modules get structured actions, not prose.

Foundation Models (on-device)

Apple's on-device LLM runs the turn. Heavier or specialized tasks (scoring pronunciation, classifying intent) use dedicated Core ML models.

SafetyFilter

Validates output against the schema and the safety policy (§ below) before anything reaches a module or the user.

ToolRouter → modules

Structured actions (create task, schedule block, generate quiz) are dispatched to feature use cases via App Intents. Side effects are explicit and auditable.

∞
MemoryStore (write)

Salient takeaways are distilled and written back, so the next turn is better. Memory is user-visible and editable.

Prompt systemVersioned & constrained

Templates are versioned assets, not strings in code. Every response uses guided generation against a Swift type, so a malformed model output simply fails validation instead of corrupting a module.

PersonalizationThe memory engine

A typed store of goals, traits, patterns and progress, plus on-device embeddings for semantic recall. It is the moat — and it never leaves the device unless synced via the user's private CloudKit DB.

Safety layer — non-negotiable

Spiritual content

Educational, non-denominational, non-extremist tone enforced by system prompt + a classifier gate. The app never issues religious rulings — it prompts personal reflection only.

Financial content

Insights are framed as awareness, never advice. A guardrail blocks buy/sell recommendations and surfaces a persistent "not financial advice" disclaimer.

Wellbeing

Crisis & self-harm intent is detected on-device and routed to resources, never to generative output. Hard fail-closed on uncertainty.

Risks & challenges

The things most likely to bite — and the mitigation.
  • ModelOn-device LLM quality. Apple's on-device model is smaller than frontier cloud models. Mitigate with tight prompts, guided generation, and Core ML task-specific models; offer an optional cloud fallback for heavy tasks.
  • ScopeSeven modules is a lot for a solo team. The roadmap ships the loop first and treats Career/Finance/Social as later, independently-shippable packages — not launch blockers.
  • TrustSpiritual & financial content liability. Hard guardrails, educational-only framing, and classifier gates. Never advice, never rulings. Legal review before Finance/Social launch.
  • DeviceHardware floor. Apple Intelligence requires recent chips. Gracefully degrade to Core ML + heuristics on older devices; gate the premium coach to capable hardware.
  • RetentionDaily-habit apps churn fast. The morning brief + streaks + evening reflection are the retention engine; instrument the loop and optimize day-1/day-7/day-30 ruthlessly.
  • PrivacyMemory is sensitive by definition. Encryption at rest, private CloudKit only, user-visible & editable memory, one-tap forget. Privacy is a feature, not a footnote.
