# ARCHITECTURE DECISION: MODULAR MONOLITH (required)
Build a SINGLE deployable Go binary structured as a modular monolith — NOT
microservices. Rationale: small team, one mobile client, MVP stage;
microservices would add deployment, networking, and debugging overhead with
no benefit yet. Enforce clean domain boundaries via internal/<domain>
packages so any package (e.g. coach or feed) can later be extracted into its
own service WITHOUT a rewrite. Rules:
- One process, one binary, one Postgres database.
- Each domain package exposes a service interface; other packages depend on
  that interface, never on another domain's repo or SQL directly.
- No cross-domain database joins across bounded contexts; go through the
  owning service. This keeps a future split cheap.
- Only extract a service when a real pressure appears (e.g. AI coach traffic
  needs independent scaling). Start monolith.

# AUTH (critical — get this right)
Endpoint: POST /v1/auth/session
Body: { provider: "google"|"apple"|"phone", idToken?, phone?, otpCode?,
        verificationId? }
Flow:
- google: verify the Google ID token (validate signature via Google JWKS,
  aud = your client id, exp). Extract sub/email/name/picture.
- apple: verify Apple identity token against Apple JWKS, aud = your bundle id.
- phone: two-step —
    POST /v1/auth/otp/start { phone } -> create otp_challenge, send SMS via
      Twilio/provider, return { verificationId }.
    POST /v1/auth/session provider=phone { verificationId, otpCode } -> verify
      hash + expiry + attempts.
- Upsert users + profiles by provider identity. If profile is new,
  onboarding_done=false.
- Return { accessToken (JWT ~15m), refreshToken (~30d), user, needsOnboarding }.
POST /v1/auth/refresh { refreshToken } -> new access token.
All /v1/** except auth require "Authorization: Bearer <accessToken>";
middleware validates JWT and injects userID into context.

# PRAYER TIMES
Implement or wrap a prayer-time calculation (astronomical) taking lat/lng,
date, madhab (Asr shadow factor: Hanafi=2, others=1) and calc_method
(MWL/ISNA/Egypt/Makkah/Karachi/Tehran fajr/isha angles). Return
Fajr,Dhuhr,Asr,Maghrib,Isha as RFC3339 local times + the "next prayer" and
seconds remaining, so the client's progress ring can render. Prefer a
well-tested Go lib if available; otherwise implement the standard algorithm
and unit-test against known values for Tashkent.
